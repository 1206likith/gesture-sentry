## Faults found and what they were
- "Car runs full speed on battery": not firmware (wheels start disabled, drive needs a command). Cause class: L298N ENA/ENB jumper caps and/or ESP32 powered badly on battery. Resolved when ENA/ENB were wired to GPIO2/GPIO15 with the caps removed: wheels stay still until commanded.
- Wheels did not turn from the glove: glove-requested duty was ~61-64/255, below what the motors need to start. Fixed in firmware: duty now starts at MIN_PWM=90 past the dead zone and ramps to MAX_PWM=200 (was 0..120). Flashed to the turret; the forward test with the new duty was NOT completed (paused).
- "Diagonal wheels in opposite directions" (earlier): each motor pair needs one motor's wires swapped. User later reported all wheels working on pulses; per-motor forward direction under glove drive NOT re-confirmed.
- Flashing the turret fails with "wrong boot mode 0xb" when ENA is on GPIO2 and the L298N pulls it up. It did flash with ENA wired in the later runs, but unplug ENA if it fails.
- USB serial ports change (COM5/COM8/COM14) when cables or boards are swapped; identify a board by its output (`link=` = turret, `GLOVE` = glove), not by COM number. At pause, both ports showed W1 boards, so neither board was on the PC.
- Disk: C: is 100% full. Host-compiler caches were put on L:.

## Glove orientation (learned, stored in the glove's flash)
Serial commands on the glove (115200): `f` capture flat, `d` capture fingers-down (do `f` then tip and send `d`), `o` one-shot version, `c` recalibrate neutral (hold flat), `r` reset. Saved frame (second calibration): fwd=(-0.98,0.09,-0.18) left=(0.08,1.00,0.04) up=(0.18,0.02,-0.98). After `d` always do `c` with the hand flat: the automatic recalibration runs while still tipped. A glove that reboots calibrates neutral in whatever pose it is in (this caused a bogus -96 degree roll once).
Verified: roll right -> pan above 90; fingers down -> tilt below 90.

## Gestures (see GESTURES.md)
Real glove results: double flick, shake (switches drive/turret) and punch were detected on the real glove and the turret acted on them. Sweeps were not (see below). STILL no longer stops the car (it conflicted with the half-second level hold used to arm the wheels); it is only reported.
Measured on this user: a jab gives a 5-8 m/s2 forward spike (slow filter), rotation under ~4.7 rad/s; the user's "sweep" is an edge-on swat with 10-14 rad/s rotation about the real vertical and a forward push.
Synthetic tests (tests/test_gestures.cpp, host compiler via Zig): all gestures >90%, 0 false actions in a simulated hour. They check logic only, not real-wrist accuracy.

## State of the source vs what is flashed
- Turret: flashed = latest source (STILL no-op, MIN_PWM 90 / MAX_PWM 200, parses `seq,pan,tilt[,evSeq,evCode]`).
- Glove: flashed = an EARLIER build (faster punch filter, yaw about the vertical, debug "GLOVE peak" lines; but before the sweep/punch-window fix). The source in glove/Gestures.h is newer and NOT flashed.
- OPEN BUG in the newer source: 1 deterministic synthetic case fails ("sweep (yaw +) -> SWEEP_LEFT") and sweep trials are 94.7%, down from 100% after the sweep/punch-window change. Investigate before flashing.
